# Сейран → облачная сессия Claude

Задачи Сейрана из `docs/tz-sunday.md`, которым не нужен мак-сервер: код, логика и тесты без живой модели и без запуска игры с игроками. Проверку на настоящей модели и в игре делает Codex на маке (`docs/seyran-codex.md`).

## Как работать

- Стартовать от ветки `seyran`: `git fetch origin && git checkout seyran`.
- Работать в своей ветке `seyran-cloud`, открыть PR в `seyran` (не в `main`). Его вливают в `seyran`.
- Ollama и модели в облаке нет. Везде, где нужен ответ модели, — заглушка `chat()` в тестах (как в `server/ai/test/*.test.js`).
- Тесты: `node --test 'server/tests/*.test.js' 'server/ai/test/*.test.js'` и `node --test 'client/tests/*.test.js'` — всё зелёное до и после.
- Трогать только файлы из списка ниже. Чужие зоны (`shared/npc-activity.js`, `content/ship_layout.json`, `client/src/world/*`) — Codex, Кирилл и Тамерлан.
- Стиль кода как в соседних файлах: комментарии по-русски и коротко, без лишних абстракций.

## Ограничения проекта

- Сервер — MacBook с 8 ГБ памяти, локальная модель `qwen3:4b-instruct` через Ollama, одна очередь (`server/ai/llm.js`). **Ни одного лишнего запроса к модели**: всё новое — поля в уже существующих вызовах или код.
- Мир меняет только сервер: клиент просит, сервер проверяет и рассылает всем.
- Новые сообщения в `shared/protocol.js` — только те, что в «Общих договорённостях» ТЗ.

## Задачи

### 1. Подсказки в диалогах обновляются после каждого ответа

Сейчас `hintsFor(agent, told)` в `server/ai/index.js` отдаёт три нерассказанные темы и меняет их, только когда тема рассказана. Нужно, чтобы после каждого ответа было 3–4 свежих варианта:

- продолжение того, о чём только что говорили (если это тема из базы — её следующий вопрос; если человек из экипажа — «А что ещё о нём скажешь?»);
- одна-две нерассказанные темы;
- «Что мне делать?», если у игрока есть задание (`currentTask`);
- «Расскажи о себе», если о себе ещё не спрашивали;
- «Прощай» — всегда последней.

Не повторять один и тот же набор два ответа подряд. Обработка новых `hintId` — в `talk()` рядом с `GENERIC_HINTS`. Клиент уже перерисовывает кнопки на каждом `npc_say` (`client/src/main.js`, обработчик ответа NPC: `$('#hints').innerHTML = …`) — проверить, что ничего не ломается.

Готово, когда: тест прогоняет 5 ответов подряд с заглушкой модели и каждый раз получает другой набор, подходящий к последней теме.

### 2. Механизм `world_patch` на сервере

- `shared/protocol.js`: `WORLD_PATCH: 'world_patch'` — `{ ops: [{ op: 'spawn'|'remove'|'set', id, kind, model, p, r, state }] }`.
- Новый `server/game/world-state.js`: динамические объекты мира (что появилось, что убрано, что изменилось), сохранение вместе со снапшотом `entities.js` в БД, полная рассылка новому и переподключившемуся игроку, частичная — всем при изменении.
- Сброс при `/reset` и при смене прохождения.

Готово, когда: тест — patch применяется, переживает рестарт (load/snapshot), новый игрок получает полное состояние.

### 3. Действия агентов

- В `content/agents/*.json` новое поле `actions`: `{ id, en: "что это (для модели)", scenes: [...], cooldownSec, patch: [ops], reply: "что агент говорит, соглашаясь" }`.
- `server/ai/understand.js`: в ту же JSON-схему добавить поле `action` — enum из действий агента, доступных в текущей сцене, плюс `"none"`. В промпт классификатора — короткий список действий. **Отдельного вызова модели нет.**
- Код решает: действие разрешено (сцена, кулдаун, предусловия) → `world-state` применяет patch и рассылает; агент отвечает с директивой «ты соглашаешься и отдаёшь приказ». Запрещено или кулдаун → вежливый отказ в образе.
- Действия:
  - Колумб (`ship_day`, `ship_evening`): зажечь фонари, поднять флаг Кастилии, убрать паруса, выдать паёк (на столе появляются сухари — их можно взять как предмет).
  - Торговец (`canary`): «покажи товар» — раскладывает товары на прилавке, после покупки (`trade`) товар с прилавка исчезает.
  - Старый Хуан (`night_story`): по ходу истории сгущается туман и тускнеет фонарь — patch по таймингам из `content/night_story.json` (сервер, без модели).
- Ложные срабатывания недопустимы: «как дела», «что мне делать», «расскажи про фонари» не запускают действие. Покрыть тестами normalize/правил (модель — заглушка).

Готово, когда: тесты на разрешение, кулдаун, сцену, отказ; patch уходит в `world-state`.

### 4. Поступки без LLM

- Задание «Вода для Америки» выполнено → в `ship_evening` на палубе стоят бочки с водой (patch при смене сцены).
- Задание «Руль Пинты» выполнено → объект «Пинта» в состоянии `repaired` (patch, рендер — Кирилл).
- Хуки — в `server/game/quests.js` (место, где ставится `status = 'done'`).

### 5. Админка: API агентов и метрики ИИ

- `GET /api/admin/agents` — список; `GET/PUT /api/admin/agents/:id` — JSON агента с проверкой (обязательные поля, типы, enum действий); после PUT — `loadAgents()` без перезапуска сервера и запись в `content/agents/<id>.json`.
- `GET /api/admin/agents/:id/memory?user=` — память агента об игроке (`turns`, `summary`); `POST /api/admin/agents/:id/memory/reset`.
- `GET /api/admin/ai` — длина очереди к модели (из `server/ai/llm.js`), средние за последние 50 ответов: понимание, ответ, перевод, озвучка (из `timings`, которые уже возвращает `talk()`).
- Доступ только с `ADMIN_TOKEN`. Каркас админки и проверку токена делает Тамерлан. Если `server/admin/auth.js` ещё нет — минимальная проверка `Authorization: Bearer <ADMIN_TOKEN>` в одном месте, чтобы потом заменить на его.
- Вкладка: `client/src/admin/agents.js` — модуль, который монтируется в контейнер вкладки. Список агентов, форма полей (личность, стиль, правила, факты, темы, действия, температура), «Сохранить», просмотр и сброс памяти игрока, блок метрик ИИ.

Готово, когда: тесты API (без токена — 401; кривой JSON — 400 с понятной ошибкой; PUT меняет ответы агента без перезапуска).
