# Бэк 1 — сервер, сеть, мир, сцены, БД

**Зона ответственности:** `server/` (кроме `server/ai/`), `shared/`, `scripts/seed-world.js`, запуск по LAN.
**Общие документы:** [README.md](README.md) (протокол, схема БД, план), [content-part1.md](content-part1.md) (сцены и задания).

Ты — «клей» команды: к 3-му часу трое должны ходить по кораблю через твой сервер. Сначала каркас, потом всё остальное.

---

## B1.1 Скелет репозитория (0–0,5 ч, вместе со всеми)

- Корневой `package.json` с workspaces `client`, `server`; скрипты `dev` (сервер + Vite параллельно), `build`, `start`, `seed`.
- `shared/protocol.js` — константы типов сообщений из README, `shared/config.js`:

```js
export const CONFIG = {
  PORT: 3000,
  TICK_HZ: 15,                 // снимки и движение
  CHUNK_SIZE: 32,              // метры
  LOAD_RADIUS: 2,              // клиент: 5×5 чанков
  SERVER_RADIUS: 3,            // сервер отдаёт чанки не дальше
  CACHE_FRACTION: 0.10,        // лимит кеша клиента
  MAX_SPEED: 7,                // м/с, бег
  INTERACT_DIST: 3,            // м
  DEMO_MODE: process?.env?.DEMO === '1',
  DEV: process?.env?.DEV === '1',
};
```

- Клиент в dev-режиме ходит на сервер через прокси Vite (`/api`, `/ws`, `/audio`), в продакшене сервер сам отдаёт `client/dist`.

**Готово, когда:** `npm run dev` поднимает сервер и Vite, страница открывается и с другого ноутбука по `http://<ip>:3000`.

## B1.2 База данных (0,5–1 ч)

- `server/db.js`: `node:sqlite` (`DatabaseSync`), файл `data/game.db`, схема из README §8 при старте (`CREATE TABLE IF NOT EXISTS`).
- Функции: `getUserByLogin`, `createUser`, `createSession`, `getSession`, `loadPlayer`, `savePlayer`, `loadAgentMemory`/`saveAgentMemory` (используются Бэком 2), `loadGameState`/`saveGameState`, `getChunk`, `putChunk`, `worldMeta`.
- `savePlayer` с задержкой: копим изменения, пишем раз в 2 с; при отключении — сразу.

**Готово, когда:** перезапуск сервера не теряет пользователей, позиции и задания.

## B1.3 Авторизация (1–1,5 ч)

- `POST /api/register {login, password}` → `{token}`. Логин 3–20 символов, пароль ≥ 4. Хеш: `crypto.scrypt` с солью, хранить `salt:hash`.
- `POST /api/login {login, password}` → `{token}` (новый токен в `sessions`). Ошибка — `401`.
- `GET /api/health` → `{ok, ollama, tts, players}` (флаги ИИ даёт Бэк 2) — для проверки перед защитой.
- Токен клиент хранит в `localStorage` и **не передаёт в URL**.

**Готово, когда:** регистрация и вход работают, неверный пароль даёт 401, повторный логин даёт новый токен.

## B1.4 WebSocket и рукопожатие (1,5–2 ч)

- `ws` на том же HTTP-сервере, путь `/ws`.
- Новое соединение «не авторизовано»: принимаем только `{t:"auth", token}`. Нет `auth` за 3 с или токен неверный → `auth_fail` и закрытие.
- После `auth_ok` соединение привязано к `userId`. Если этот пользователь уже подключён в другой вкладке, старое соединение закрываем.
- Пинг раз в 10 с, мёртвые соединения закрываем.
- Ограничения: сообщение ≤ 4 КБ, `chat` ≤ 300 символов, `npc_talk` не чаще 1 раза в 2 с.
- `auth_ok` содержит: `you`, сохранённое `state` (роль, сцена, зона, позиция, инвентарь, задания), `world` (метаданные чанков: `zones`, `totalChunks`, `totalBytes`, `cacheLimit`), текущую сцену с `startAt`.

**Готово, когда:** без токена отключает; с токеном приходит `auth_ok`.

## B1.5 Игроки и синхронизация движения (2–2,5 ч)

- `server/game/players.js`: в памяти `Map<userId, {ws, name, role, zone, p, r, a, ready, connected}>`.
- `move`: принимаем только в игровых сценах (`ship_day`, `canary`, `ship_evening`). Проверка: перемещение за сообщение ≤ `MAX_SPEED × dt × 1.5 + 0.5`, иначе игнорируем.
- Цикл `TICK_HZ`: каждому клиенту `snapshot` с игроками **его зоны** (кроме него самого).
- `player_join`/`player_leave` при входе/выходе.
- При отключении игрок 60 с остаётся в партии как «отключён», затем удаляется из проверок готовности.

**Готово, когда (синхронизация 1, час 3):** три вкладки/ноутбука видят друг друга, движение плавное (интерполяция — на фронте).

## B1.6 Лобби и роли (2,5–3 ч)

- Роли: `grumete`, `piloto`, `lengua`. Выбор роли — сообщение `interact` с `id: "role:piloto"` в сцене `lobby` (или отдельный тип `pick_role`, если удобнее — тогда добавь в `protocol.js`).
- Роль занята → отказ через `notice`. Роль сохраняется в `player_state`.
- `lobby` рассылается при каждом изменении.

## B1.7 Режиссёр сцен (3–4 ч, затем доработка)

`server/game/director.js` + `content/scenes.json`:

```json
[
  { "id": "lobby", "type": "lobby", "zone": "ship", "advance": "all_ready", "next": "intro" },
  { "id": "intro", "type": "cutscene", "duration": 90, "demoDuration": 45, "advance": "timer_or_skip", "next": "ship_day" },
  { "id": "ship_day", "type": "play", "zone": "ship", "tod": 0.4, "duration": 600, "demoDuration": 180,
    "advance": "quests", "onComplete": [ {"say": "columbus_rudder"}, {"wait": 6000} ], "next": "cut_canary",
    "spawns": { "grumete": [0,1.6,8], "piloto": [0,3.2,-9], "lengua": [1,1.6,0] } },
  { "id": "cut_canary", "type": "cutscene", "duration": 20, "next": "canary" },
  { "id": "canary", "type": "play", "zone": "canary", "tod": 0.45, "demoDuration": 180,
    "advance": "all_ready", "readyAt": "boat", "next": "cut_evening" },
  { "id": "cut_evening", "type": "cutscene", "duration": 15, "next": "ship_evening" },
  { "id": "ship_evening", "type": "play", "zone": "ship", "tod": 0.72, "demoDuration": 120, "advance": "quests_and_ready", "next": "cut_night" },
  { "id": "cut_night", "type": "cutscene", "duration": 25, "next": "night_story" },
  { "id": "night_story", "type": "locked", "zone": "ship", "tod": 0.95, "duration": 150, "advance": "timer", "next": "sleep",
    "seats": [[2,1.6,3],[-2,1.6,3],[0,1.6,5]] },
  { "id": "sleep", "type": "cutscene", "duration": 10, "next": "end" }
]
```

- Смена сцены: `startAt = now + 1500` (чтобы все клиенты начали одновременно), телепорт игроков в `spawns`/`seats`, рассылка `scene`, сброс `ready`.
- Условия `advance`: `all_ready` — все подключённые нажали `ready`; `quests` — все обязательные задания сцены выполнены; `quests_and_ready`; `timer`; `timer_or_skip` — таймер или все проголосовали `skip_vote`.
- **Страховка:** если у сцены есть `duration`/`demoDuration` и время вышло, переходим дальше сами (незакрытые задания засчитываем).
- `onComplete` — простой список действий: `say` (разослать готовую реплику из `content/lines.json` как `npc_say`), `notice`, `wait`.
- Время суток: рассылка `tod` раз в 2 с; в `ship_day` можно плавно двигать от 0.35 к 0.5.
- Текущая сцена хранится в `game_state` — после перезапуска сервера игра продолжается с той же сцены.
- **Dev-команды** (только при `DEV=1`) в чате: `/scene <id>`, `/reset`, `/give <item>`, `/done` (выполнить мои задания).

**Готово, когда:** в демо-режиме сцены переключаются по условиям и таймерам у всех одновременно.

## B1.8 Мир и чанки (3–5 ч)

### Генерация (`scripts/seed-world.js`, `npm run seed`)
- Детерминированный шум (небольшая реализация simplex или пакет `simplex-noise`) с фиксированным seed.
- Остров `canary` 512×512 м: высота = шум × радиальное затухание к краям, 0…40 м, уровень моря 0. Центр города (~120×120 м вокруг пристани) выравниваем до 2–4 м.
- Высоты: сетка 33×33 на чанк (края совпадают с соседями), округлить до 0,1 м.
- Объекты: ручные из `content/canary_layout.json` (пристань, колодец, рынок, верфь, дома, церковь, NPC-точки) + процедурные: канарские пальмы, драконовы деревья, камни, кусты (выборка с минимальным расстоянием, только на подходящей высоте, не в городе и не на дорожках).
- Каждый объект попадает в свой чанк по координатам. Формат чанка:

```json
{ "zone": "canary", "cx": 7, "cz": 8, "size": 32,
  "h": [ /* 1089 чисел */ ],
  "objects": [ { "id": "palm_812", "m": "palm_canary", "p": [231.4, 3.2, 270.1], "r": 1.2, "s": 1.1 } ],
  "interact": [ { "id": "well", "m": "well", "p": [240, 3, 255], "kind": "well" } ] }
```

- Зона `ship`: один чанк `0,0` с точками предметов и NPC из `content/ship_layout.json`. Координаты подбирает Фронт 1, когда поставит модель корабля.
- Пишем в таблицу `chunks` (поле `bytes` = длина JSON). Мета: число чанков по зонам, `totalChunks`, `totalBytes`, `cacheLimit = floor(0.1 × totalChunks)`.

### Выдача
- `chunk_req {zone, keys}`: для каждого ключа проверяем, что зона = зоне игрока и чанк в радиусе `SERVER_RADIUS` от его позиции. Иначе `chunk_denied`. Не больше 30 ключей за запрос.
- Ответ `chunk` по одному на ключ. Добавляем в данные текущее состояние интерактивных объектов из `entities` (например, колодец уже использован).
- Счётчик в памяти: сколько чанков отдано каждому игроку (для `/api/health` и защиты).

**Готово, когда:** при ходьбе по острову клиент получает только соседние чанки, запрос дальнего чанка отклоняется.

## B1.9 Объекты, предметы, инвентарь (5–6 ч)

- `server/game/entities.js`: состояние всех предметов `{id, zone, p, holder}` и интерактивных объектов `{id, state}` (часы: `emptyAt`; колодец; шлюпка: кто сел).
- `pickup`: предмет свободен, игрок в той же зоне и ближе `INTERACT_DIST` → `holder = userId`, разослать `entity`, игроку `inventory`. Гонка двух игроков решается тем, чьё сообщение пришло первым.
- `use {item, target}`: передача предмета NPC (доски → плотник) или использование (вино).
- Предметы, выданные сценой: в начале `canary` выдаём переводчику `purse`, юнге — ничего (бочонок он берёт сам).
- Описания предметов — `content/items.json` (общий для фронта и сервера).

## B1.10 Движок заданий (5–6,5 ч)

`content/quests.json`:

```json
{ "id": "q_water", "scene": "canary", "role": "grumete", "title": "Вода для Америки",
  "steps": [
    { "type": "pickup", "item": "barrel", "text": "Возьми бочонок у шлюпки" },
    { "type": "interact", "target": "well", "text": "Наполни его у колодца" },
    { "type": "deliver", "item": "barrel_full", "target": "boat", "text": "Отнеси в шлюпку" }
  ] }
```

- Типы шагов: `pickup`, `interact` (+`count`), `deliver`, `minigame` (`game`, `success: true`), `topics` (`npc`, `need`, `of: [...]`) — засчитывается по `topicsTold`, который возвращает ИИ (см. ниже), `trade_complete`, `any_of` (`need: 3`, `of: [шаги]`) — для праздника.
- События от обработчиков сообщений → `quests.onEvent(userId, event)` → продвинуть шаг → `quest {id, status, progress, total}` игроку → проверить условие сцены.
- **Отсутствующие роли:** при входе в сцену задания ролей, которых нет среди подключённых, становятся общими: выполнить их может любой игрок.
- **Журнал действий** (`log` в `player_state`): короткие коды `found_astrolabe`, `latitude_correct`, `traded_hard`, `rudder_fixed` — Бэк 2 подмешивает их в промпт агентам.

**Торговля** (код здесь, текст — у Бэка 2): `content/npcs.json` → у торговца `goods: [{item, basePrice, minPrice}]`. `trade {item, offer}`: `offer ≥ minPrice` и хватает денег → продано; иначе встречная цена `max(minPrice, (offer + current) / 2)`; три предложения ниже `minPrice` → цена +5. Итог передаётся Бэку 2 для реплики.

## B1.11 Связка с ИИ (Бэк 2)

Бэк 2 экспортирует из `server/ai/index.js`:

```js
// Вызывает Бэк 1 на npc_talk / npc_hint / после trade
talk({ userId, npc, text, hintId, context, tradeResult }) → Promise<{
  en, ru, audio,          // строки и URL
  hints: [{ id, ru }],
  topicsTold: ['why_west'] // для шагов "topics"
}>
playLine(lineId) → { npc, en, ru, audio } // готовые реплики
status() → { ollama: bool, tts: bool }
```

`context` собираешь ты: `{ role, name, scene, inventory, questsDone, log }`.

Порядок: `npc_talk` → сразу `npc_thinking` → `await ai.talk(...)` → `npc_say` игроку → `quests.onEvent({type:"topics", ...})`. Пока Бэк 2 не готов, сделай заглушку `talk`, которая возвращает фиксированную фразу.

## B1.12 Сохранение и переподключение (6,5–7,5 ч)

- Сохраняем: роль, зона, позиция, инвентарь, задания, журнал; глобально — сцена и объекты.
- При повторном входе `auth_ok` возвращает всё это; клиент ставит игрока туда же. Если сцена уже другая (пока он был offline), ставим в `spawn` текущей сцены.
- Если подключился посреди катсцены — клиент получает `scene` с исходным `startAt` и может показать остаток или сразу ждать следующую сцену.

**Готово, когда:** закрыл вкладку посреди Канар → открыл → стоит там же, с бочонком в руках, задание на том же шаге.

## B1.13 Запуск по LAN и демо (8–10 ч)

- Сервер слушает `0.0.0.0`, при старте печатает `http://<LAN-IP>:3000`.
- В роутере закрепить IP за Mac-сервером. В macOS разрешить входящие соединения для `node` (Настройки → Сеть → Firewall).
- `npm run start:demo` = сборка клиента + `DEMO=1 node server`.
- `npm run reset` очищает `game_state` и прогресс, но не пользователей — для повторного прогона демо.
- Проверить на трёх ОС в Chrome **без интернета**.
