# Санджар: план воскресных изменений

Основа: полностью прочитанное [ТЗ](tz-sunday.md), `main` на коммите `99e9e83`.
Этот PR пока содержит только план для обсуждения, игровые изменения ещё не внесены.

## Работа с Git

- Рабочая ветка Санджара — `sanjar`, созданная от актуального `main`.
- Перед следующими изменениями получать свежий `origin/main` и объединять его с `sanjar`, сохраняя свою работу.
- Публиковать изменения через PR `sanjar` → `main`. Самостоятельно PR не сливать.
- Не переносить старые ветки поверх новой основы: предыдущая работа уже вошла в `main`.

## Порядок реализации

1. Исправить четыре текущих пункта: расстановка предметов только в `interact`, видимый песок часов, компактная выносливость, ЛКМ в пустоту. Сохранить идентификаторы предметов и задания. Некоторые механизмы уже есть: сначала воспроизвести дефекты, затем исправлять.
2. Согласовать общие сообщения. Реализовать постановку предмета по прицелу с серверной проверкой владения, зоны, расстояния и допустимой поверхности. Передавать расход оставшихся порций вместе с предметом, исключить дублирование.
3. Добавить серверное состояние дверей и крышек, запрос `toggle`. Сами анимации петель согласовать с Кириллом.
4. Добавить небольшой модуль физики: фиксированный шаг, гравитация, коллизии шара/коробки, отскок и трение. Бросок использует подтверждённые сервером начальные условия; сервер подтверждает конечную позицию. Крен и инерция используют общие параметры времени, а не произвольное локальное время кадра.
5. Подключить подбор объектов, появившихся через `world_patch`, и события предметных действий для реакций NPC.
6. Проверить на нескольких клиентах: перемещения и состояния совпадают, повторный запрос не создаёт копий предметов, переподключение восстанавливает состояние, кеш мира остаётся в пределах 10%.

## Границы работы

- Свои файлы: `client/src/game/*`, новый `client/src/world/physics.js`, `server/game/item-actions.js`, `server/game/entities.js`, `content/items.json`.
- По указанным в ТЗ исправлениям: точечные правки `client/src/main.js` (использование предмета и подключение своего модуля), `client/src/ui/style.css` (выносливость), `client/src/world/props.js` (песок часов).
- `content/ship_layout.json`: только `interact`; раздел `npcs` принадлежит Сейрану.
- `shared/protocol.js`: изменения после согласования общей схемы. Не добавлять чужие `ping`, метрики и админ-API.
- Не брать админку, расчёт широты, остановку Колумба, таймер истории, агентов, маршруты NPC, животных, таино и общий рендер `world.applyPatch()`.
- Если для серверной маршрутизации или подключения к миру нужны общие файлы, согласовать точечные вызовы своих модулей с владельцем файла.

## Что нужно согласовать с командой

- **Тамерлан:** оставить обработку `place`/`throw`/`toggle` модулю Санджара; согласовать единый отправитель `world_event`, чтобы события не дублировались. Определить формат `entity` для состояния движущегося предмета.
- **Сейран:** для `world_patch` с подбираемым объектом нужны `id`, `item`, `model`, `zone`, позиция и остаток порций. Серверный реестр должен знать об объекте до подбора. Раздел `npcs` Санджар не меняет.
- **Кирилл:** общий рендер патчей и анимация петель остаются у него; Санджар обеспечивает физическое состояние, взаимодействие и песок. Согласовать регистрацию новых объектов в `interactables` и идентификаторы дверей/крышек. Для часов нужен стабильный доступ к группе колб и серверное время начала/длительности: одного `emptyAt` недостаточно для одинакового заполнения после позднего входа.
- **Всем:** до реализации согласовать расширение общих сообщений: для броска нужны идентификатор объекта/броска, зона и серверное время старта; для восстановления — финальная позиция и состояние. В списке типов `world_event` из ТЗ пока нет `throw`, хотя событие броска требуется разделом Санджара.

## Проверки перед готовым PR

Серверные тесты владения, дистанции, смены зоны и повторных запросов; тесты фиксированного шага физики и восстановления состояния; сборка клиента. Ручная проверка ЛКМ, часов и HUD на узком окне, затем проверка бросков и дверей с двумя клиентами. Реализация и результаты будут добавляться в этот PR по мере выполнения.
