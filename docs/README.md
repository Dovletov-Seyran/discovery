# «1492» — ТЗ, часть 1 (сторона Колумба)

Многопользовательская браузерная игра на three.js о первом плавании Колумба. Часть 1 — от отплытия до ночи перед открытием Америки. Часть 2 (таино) будет описана отдельно.

**Бюджет:** ~10 часов на 4 человек (2 фронта, 2 бэка). **Защита:** 10–15 минут.

## 1. Что должно быть на защите (требования задания → как закрываем)

| Требование | Решение |
|---|---|
| three.js в браузере | Клиент на three.js + Vite, Chrome |
| Мультиплеер по LAN/Wi-Fi | 1 Mac-сервер, 3 клиента (Mac, Windows, Linux), один роутер без интернета |
| Объекты подгружаются с сервера по положению игрока | Мир разбит на чанки 32×32 м, клиент запрашивает чанки вокруг себя, сервер проверяет позицию |
| На клиенте ≤ 10% данных мира | LRU-кеш чанков с жёстким лимитом, счётчик «загружено N% мира» в углу экрана |
| Клиенты получают движения других игроков | Снимки позиций 15 раз/с, интерполяция |
| Двунаправленный обмен после авторизации | Логин по HTTP → токен → WebSocket, первое сообщение `auth`, без него соединение закрывается |
| Состояние игроков в БД | SQLite (`node:sqlite`): позиция, сцена, инвентарь, задания, память агентов |
| ИИ-агенты с индивидуальностью, адаптируются | Колумб, Старый моряк, Торговец: Qwen локально + база фактов + память «что уже рассказал» + журнал действий игрока |
| Только локальные вычисления, без интернета | Ollama, Kokoro, все модели и ассеты скачаны заранее |
| Социальный смысл | История, география, математика (широта по астролябии), английский язык (NPC говорят по-английски, субтитры по-русски) |
| Красиво и производительно | Стилизованный low-poly, вода/небо/туман/свет, инстансинг, 2 пресета качества |

## 2. Объём: что обязательно, а что если успеем

Правило: **сначала всё из колонки MVP работает от начала до конца, потом украшения.** К 8-му часу новые фичи не начинаем.

| MVP (обязательно) | Если успеем |
|---|---|
| Регистрация/вход, лобби с выбором роли | Анимации танцев |
| 3 игрока ходят по кораблю и видят друг друга | Карты («старшая карта» → упрощённая «примера») |
| Вода, небо, 2 корабля на фоне, смена день → закат → ночь | Армрестлинг (QTE) |
| Предметы, инвентарь, по 1 заданию на роль в каждой сцене | Второе задание на роль |
| Колумб, Старый моряк, Торговец на LLM с голосом и переводом | Позиционный звук голоса NPC |
| Остров Канар с подгрузкой чанков и счётчиком % | Жители острова бродят по маршрутам |
| Вступление: пергамент + голос + субтитры | Анимированная карта маршрута |
| Ночь: туман, лампа, страшная история, звуки, «Бу!», сон | Голосовой чат |
| Сохранение и восстановление после переподключения | Экран «что вы узнали» с итогами |

## 3. Архитектура

```
┌─────────────── Mac M3 8 ГБ (только сервер) ────────────────┐
│ Node.js 24  :3000                                           │
│  ├─ HTTP: статика клиента, /api/register, /api/login,       │
│  │        /audio/* (сгенерированные реплики)                │
│  ├─ WebSocket /ws: авторизация, движение, чанки, сцены,     │
│  │        задания, чат, диалоги с NPC                       │
│  ├─ SQLite (node:sqlite) data/game.db                       │
│  ├─ ИИ: Ollama :11434 (Qwen ~4B)                            │
│  └─ Голос: kokoro-js (ONNX, CPU)                            │
└─────────────────────────────────────────────────────────────┘
          ▲  Wi-Fi роутер без интернета  ▲
   Chrome (Mac)      Chrome (Windows)      Chrome (Linux)
```

**Принципы:**
- **Сервер главный.** Он решает, кто что подобрал, выполнено ли задание и когда сменилась сцена. Клиент только показывает и присылает намерения.
- **LLM не управляет игровой логикой.** Цены, выполнение заданий и переходы считает код. LLM только говорит в образе.
- **Всё настраивается в `shared/config.js` и `content/*.json`**, а не захардкожено. Так можно быстро включить демо-режим с короткими сценами.

## 6. Протокол WebSocket

Все сообщения — JSON `{ "t": "<тип>", ... }`. Координаты — метры, `p: [x, y, z]`, поворот `r` — yaw в радианах. Время — `Date.now()` сервера.

### Клиент → Сервер

| t | Поля | Когда |
|---|---|---|
| `auth` | `token` | Первое сообщение; без него за 3 с сервер закрывает соединение |
| `move` | `p, r, a` (`a`: `idle`/`walk`/`run`/`sit`) | 15 раз/с, только если что-то изменилось |
| `chunk_req` | `zone, keys: ["3,5", ...]` | Клиенту нужны чанки рядом |
| `chunk_drop` | `zone, keys` | Клиент выгрузил чанки (для статистики) |
| `interact` | `id` | Нажал E на объекте (часы, колодец, шлюпка…) |
| `pickup` | `id` | Подобрал предмет |
| `use` | `item, target?` | Использовал/отдал предмет |
| `minigame` | `game, result` | Итог мини-игры (`astrolabe`, `hourglass`, `cards`, …) |
| `chat` | `text` | Текстовый чат игроков |
| `npc_talk` | `npc, text` | Игрок написал NPC (по-русски) |
| `npc_hint` | `npc, hint` | Нажал кнопку-подсказку |
| `trade` | `npc, item, offer` | Предложение цены торговцу |
| `ready` | `value: true/false` | Готов к переходу в следующую сцену |
| `skip_vote` | — | Голос за пропуск катсцены |
| `scare` | `target` | «Бу!» (только в сцене `night_story`) |

### Сервер → Клиент

| t | Поля | Когда |
|---|---|---|
| `auth_ok` | `you: {id, name, role}, state, world` | После успешной авторизации. `state` — сохранённое состояние, `world` — метаданные мира |
| `auth_fail` | `reason` | Неверный токен |
| `lobby` | `players: [{id, name, role, ready}]` | Изменилось лобби |
| `snapshot` | `tick, players: [{id, p, r, a}]` | 15 раз/с, только игроки той же зоны |
| `player_join` / `player_leave` | `id, name, role` | Вход/выход |
| `scene` | `id, startAt, tod, zone, spawn?, seat?` | Смена сцены. Клиенты запускают катсцену/сцену синхронно по `startAt`. `spawn` — куда поставить этого игрока, `seat` — место у фонаря в `night_story` |
| `tod` | `value` (0…1) | Время суток (раз в 2 с) |
| `chunk` | `zone, key, data` | Ответ на `chunk_req` |
| `chunk_denied` | `zone, key, reason` | Чанк слишком далеко от игрока |
| `entity` | `id, state` | Изменился объект (предмет подобран, бочка наполнена…) |
| `inventory` | `items: [...]` | Новый инвентарь игрока |
| `quest` | `id, status, progress, total` | Прогресс задания |
| `party` | `ready: {id: bool}, waitingFor: [...]` | Кто ещё не готов к переходу |
| `chat` | `from, text` | Сообщение игрока |
| `npc_thinking` | `npc` | NPC «думает» — показать индикатор |
| `npc_say` | `npc, en, ru, audio, hints: [{id, ru}]` | Реплика NPC: английский текст, русские субтитры, URL аудио, подсказки |
| `scared` | `by` | Тебя напугали |
| `notice` | `text` | Короткое уведомление внизу экрана |

Пример:
```json
{ "t": "npc_say", "npc": "columbus",
  "en": "West, always west. The Khan's ports lie beyond this sea.",
  "ru": "На запад, только на запад. Порты Великого хана лежат за этим морем.",
  "audio": "/audio/rt/columbus_1730371234.wav",
  "hints": [{ "id": "why_west", "ru": "Почему не вокруг Африки?" }] }
```

## 7. Мир и чанки (требование «≤10%»)

- **Зоны:** `ship` (корабль, 1 чанк с предметами и NPC), `canary` (остров 512×512 м = 16×16 = **256 чанков** по 32 м). В части 2 добавится остров таино (ещё 256).
- **Чанк** содержит высоты рельефа (33×33), список объектов (`{id, m, p, r, s}`) и интерактивные объекты. Модели (GLB) — это библиотека ассетов, а не данные мира, они кешируются браузером отдельно.
- **Клиент** держит чанки в радиусе 2 вокруг себя (5×5 = 25). Лимит кеша — `floor(0.1 × totalChunks)`, лишнее вытесняется по LRU. Туман на ~70 м прячет границу подгрузки.
- **Сервер** отдаёт чанк, только если он в радиусе 3 от реальной позиции игрока. Иначе `chunk_denied`. Так подгрузка действительно зависит от положения.
- **В HUD** (по F3 и всегда на защите): `Мир: 23/257 чанков (8.9%) · 118 КБ / 1.4 МБ`.

## 8. База данных (SQLite)

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY, login TEXT UNIQUE NOT NULL,
  pass_hash TEXT NOT NULL, created_at INTEGER NOT NULL);
CREATE TABLE sessions (
  token TEXT PRIMARY KEY, user_id INTEGER NOT NULL REFERENCES users(id),
  created_at INTEGER NOT NULL);
CREATE TABLE player_state (
  user_id INTEGER PRIMARY KEY REFERENCES users(id),
  role TEXT, zone TEXT, x REAL, y REAL, z REAL, ry REAL,
  inventory TEXT,   -- JSON
  quests TEXT,      -- JSON {questId: {status, progress}}
  log TEXT,         -- JSON журнал действий для ИИ: ["found_astrolabe", ...]
  updated_at INTEGER);
CREATE TABLE agent_memory (
  user_id INTEGER, agent_id TEXT,
  told TEXT,        -- JSON [cardId, ...] что агент уже рассказал
  history TEXT,     -- JSON последние 6 реплик
  PRIMARY KEY (user_id, agent_id));
CREATE TABLE game_state (
  id INTEGER PRIMARY KEY CHECK (id = 1),
  scene TEXT, scene_started_at INTEGER, entities TEXT); -- JSON состояния объектов
CREATE TABLE chunks (
  zone TEXT, cx INTEGER, cz INTEGER, data TEXT, bytes INTEGER,
  PRIMARY KEY (zone, cx, cz));
```

Сохранение: при изменении (с задержкой 2 с), при отключении и раз в 10 с.

## 12. Сценарий защиты (10–15 мин, `DEMO_MODE=1`)

1. **(1 мин)** Показать: роутер без интернета, сервер на Mac, три ноутбука на разных ОС. Регистрация, лобби, выбор ролей.

6. **(2 мин)** Вечер и ночь: история, звуки, «Бу!», сон.
7. **(1 мин)** Титр «12 октября 1492. Рассвет…» как тизер части 2. Вопросы.
